# Sentinel KYC — Angular Conversion

Angular port of the KYC compliance console POC, built to the finalized scope:

- Angular **21 LTS**, standalone components throughout (no NgModules)
- TypeScript, strict compiler + strict template checks (see `tsconfig.json`)
- **Zoneless change detection**; **Signals** for local/UI state, **RxJS** reserved for async streams (HTTP, etc.)
- **Angular CDK** for behavior primitives (Overlay/positioning) — no Angular Material component layer, no Bootstrap
- Custom **SCSS design-token system**, carried over 1:1 from the original CSS custom properties — all 7 themes preserved
- Custom **SVG icon set**, ported as an Angular icon component + registry — no Font Awesome
- **i18n** via `@jsverse/transloco`, with `DirectionService` handling RTL for Arabic
- **Vitest** for unit tests, **Playwright** for end-to-end
- `angular-eslint` + Prettier for code quality

## Getting started

This was hand-authored to the target file layout rather than generated by `ng new`,
since dependency resolution requires network/npm access. Before running it:

```bash
npm install
npm start        # ng serve
npm test         # Vitest unit tests
npm run test:e2e # Playwright e2e (starts the dev server automatically)
npm run lint
```

`package.json` pins dependency ranges (`^21.0.0`, etc.) rather than exact patch
versions — run `npm install` once to let npm resolve and lock the exact versions
current at install time, then commit the resulting `package-lock.json`.

## How each piece of the original vanilla-JS POC maps over

| POC mechanism | Angular equivalent |
|---|---|
| `manualExpanded` / `openModule` globals | `RailStateService` (signals) |
| `toggleDD()` / `closeAllDD()` / manual `document` click listener | `HeaderMenuService` + `HeaderDropdownComponent` (CDK Overlay handles backdrop/dismiss) |
| `positionFlyout()` (manual `getBoundingClientRect` math) | `RailFlyoutService` + CDK `cdkConnectedOverlay` (`ConnectedPosition`) |
| `THEMES` object + `selectTheme()` + `body.dataset.theme` | `ThemeService` (signal + `effect()` syncing to `<body>`) |
| `:root` / `body.dark` / `body[data-theme]` CSS custom properties | `src/styles/_tokens.scss` — same variable names, same values |
| Raw SVG strings inlined per element | `IconComponent` + `icon-registry.ts` |
| — (new capability) | `ToastService`/`ToastComponent` — reusable success/error/info notifications, mounted once in the shell |
| — (new capability) | `ModalComponent` — reusable centered dialog on CDK Overlay's `GlobalPositionStrategy`, used for both the person form and delete confirmation |
| Hardcoded `EN`/`BN`/`AR` strings | `@jsverse/transloco` + `assets/i18n/*.json` + `DirectionService` for RTL |
| `mods` array (module → category → items) | `NAV_MODULES` in `core/models/nav-module.model.ts` |

## Navigation tree (ported from the NexaCore POC)

The rail was rebuilt around a genuinely recursive 5-level tree — **Module Group → Module →
Category (Operation/Setup/Report) → Feature Group → Feature** — ported from a separate,
larger POC (`NexaCore Enterprise`) that generalized this console's design system across
9 business verticals (Banking, Survey, POS, Health & Medical, Education, E-Commerce,
Administration, Security, Reporting). A few notes on the port:

- **Fixed a real bug in the source**: its `categories()` builder produced `[Operation, Report, Setup]`
  — Report before Setup — inconsistent with the Operation → Setup → Report order used everywhere
  else in both that POC and this app. `nav-tree.model.ts` uses the corrected order; see
  `nav-tree.model.spec.ts` for a regression test.
- **Every module shares the same default Setup/Report groups** in the source data (only the
  Operation category actually differs per module) — carried over as-is via `DEFAULT_SETUP_GROUPS`/
  `DEFAULT_REPORT_GROUPS` in `nav-tree.model.ts`.
- **Simplified the mega panel's context art**: the source generated bespoke per-vertical SVG
  line art; this port uses the Module Group's emoji in an accent-tinted panel instead, to avoid
  ~9 hand-drawn illustrations for a POC. Swap `MegaPanelComponent`'s `.mega-context-art` for real
  art/illustrations when this becomes a production screen.
- **Only one feature leaf is wired to a real route** — `Banking > Core Banking > Operation >
  Customer Management > Customer Search` navigates to `/customers/list` (the People CRUD page).
  Every other one of the ~500 leaves updates the breadcrumb/title only, same as the source POC —
  there's no backing screen for the rest yet. Add a `route` to any `NavNode` leaf in
  `nav-tree.model.ts` to wire up more as real screens get built.
- **Icon-view (collapsed rail) only ever shows level-1 rows** — levels 2/3 aren't just
  CSS-hidden, they're never added to the DOM at all in that state (see `RailNavComponent.visibleRows`),
  matching the source's behavior exactly.



`AuthService` is a self-contained in-memory demo (one seeded account: `amina.osei@sentinel-kyc.com` / `Password123`,
matching the profile shown in the header), with session persisted to `localStorage` and simulated network
latency/failure via RxJS. Swap `login()`/`register()`'s bodies for real `HttpClient` calls when a backend exists —
`AuthService`, `authGuard`/`guestGuard`, and both auth components are otherwise ready to go.

## What's intentionally left as a stub

- **SSO app launch**: `launchApp()` in the header stubs the redirect — wire to your
  SSO broker's signed-URL endpoint.
- **Customers / KYC / Admin feature routes**: only `Dashboard` and `Customers > List`
  are wired up in `app.routes.ts`; the remaining modules follow the same
  `loadComponent` pattern once those screens are built.
- **Real notification/task data**: currently static markup in the header
  dropdowns — swap for a service + `HttpClient`/RxJS stream when the API exists.
